# 组织与团队空间（第一版）

组织用于企业或团队统一付款、成员共享使用。用户保留个人空间，一个账号可加入多个组织；余额、API Key、使用记录和任务归属按空间保存。

## 后台启用

在「系统设置 → 运维 → 系统行为」配置「组织工作空间」，默认开启。关闭时隐藏用户入口，暂停组织管理接口和组织 Key，保留所有数据。重新开启后恢复使用。已付款订单和已提交任务继续按原组织结算，避免因关闭开关丢失资金或误扣个人余额。

## 使用流程

1. 从顶部空间切换器进入组织管理，创建组织。
2. 按邮箱邀请成员；邀请有效期为 7 天。收件人使用相同邮箱的账号登录，在组织页面接受邀请。
3. 所有者或管理员可从个人余额转入资金，也可以在组织钱包使用站点现有支付渠道充值。
4. 成员在组织内只需填写名称即可创建组织 Key。用该 Key 调用 API，费用直接从组织余额扣除。
5. 在顶部切换空间后，Key、使用日志、任务日志、数据看板和钱包使用当前空间的数据。账号资料、登录、安全设置与平台管理仍属于用户账号或平台。

在线调试（Playground）目前继续使用个人模型权限和个人余额，页面会在组织空间内提示这一点。需要从组织余额扣费时，使用组织 API Key 从客户端调用。

## 权限

| 操作 | 所有者 | 组织管理员 | 成员 |
| --- | --- | --- | --- |
| 创建、使用自己的组织 Key | 可以 | 可以 | 可以 |
| 查看自己的组织用量与日志 | 可以 | 可以 | 可以 |
| 查看组织汇总、全部成员用量和组织 Key | 可以 | 可以 | 不可以 |
| 充值、转入、查看组织钱包流水 | 可以 | 可以 | 不可以 |
| 邀请、移除普通成员及设置其月度额度 | 可以 | 可以 | 不可以 |
| 任命或管理组织管理员 | 可以 | 不可以 | 不可以 |
| 转移组织所有权 | 可以 | 不可以 | 不可以 |
| 退出组织 | 先转移所有权 | 可以 | 可以 |

组织管理员与平台管理员是不同角色。普通成员的标准看板展示自己的组织使用记录，组织管理页向有管理权限的成员提供团队汇总。个人订阅额度不会用于组织 Key。

## 资金和额度

- 组织使用现有模型、渠道与分组定价。创建时继承创建者的分组，成员的个人订阅和余额不用于组织调用。
- 个人转入会同时扣减个人余额、增加组织余额并记录流水，整笔事务成功才生效；转入不是新的付费充值，不重复给予充值优惠或推荐奖励。
- 在线充值订单保存组织 ID。付款完成后，按订单归属直接入账，用户切换空间、角色变化或组织开关关闭都不会改写该归属。支付回调、组织入账与流水记录共用事务。
- 请求先预留组织余额和成员月度预算，完成后按实际用量多退少补。异步任务沿用提交时的组织和月份，成员退出后仍结清已经提交的任务。
- 成员月度额度 `0` 表示不额外限制；按 UTC 自然月计算。每次新请求检查剩余余额及预算。实际费用高于预扣时仍需结清，可能形成余额欠款；补足之前新请求会被拒绝。
- 成员被移除或主动退出后，其组织 Key 停用且不可重新启用，历史用量和任务仍保留。

## 数据和通知

组织 Key 显示所属组织、创建者、状态、创建时间、最近使用时间与到期时间。第一版组织 Key 默认不过期，成员资格和 Key 状态共同控制可用性。

组织邀请、到期前 24 小时提醒、角色变化、移除成员和所有权转移通知复用已有 SMTP 或 Resend 配置。到期提醒使用现有后台任务框架，保存发送状态，避免多实例重复处理。邮件未配置或发送失败时，已保存的组织操作不会回滚，用户仍可通过站内待处理邀请加入。通知是组织业务邮件，与个人营销邮件偏好分开。

组织钱包沿用站点现有在线支付渠道。个人兑换码、个人订阅、推荐奖励和个人发票资料管理入口不会出现在组织钱包中。第一版不提供组织余额转回个人、银行退款申请或独立的企业开票资料管理。

## 验证范围

新增回归用例覆盖成员权限、跨组织访问、Key 失效、月度额度、预扣结算退款、转入事务回滚、在线充值的钱包归属及重复回调。前端生产构建通过。当前机器只有 Go 1.25.0，低于 `go.mod` 要求的 Go 1.26.10，后端测试尚未运行，需在符合要求的环境执行。数据库代码使用 GORM 兼容 SQLite、MySQL、PostgreSQL；静态检查不代表各数据库的运行验证已通过。
